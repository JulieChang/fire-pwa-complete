V1 基準原則

本文件定義 Personal FinOps Planner 在 V1 階段的系統邊界與治理原則。核心原則是：計算與判斷可以由系統與 AI 輔助，但任何高影響行動均保留在人類決策層，且所有重要假設、方法與版本變更必須可解釋、可追溯。

一、產品循環

Dashboard 是每日入口，只呈現今天該知道與該做的事，不承擔複雜分析。深度分析、模擬與比較應留在情境規劃與 FIRE 規劃模組中。

二、財務智能

財務智能負責計算與判斷，包含資產配置、提領率、壓力測試與多情境比較。輸出必須為可解釋的建議，清楚揭露關鍵假設與判斷依據，但不得自動執行任何交易、下單或資金移轉。

三、Dashboard 入口

Dashboard 僅顯示四項核心資訊：淨值、現金月數、本月可投資金額、與 FIRE 軌道偏差。每一項指標都附上一句簡短說明，協助使用者快速理解目前狀態與下一步。

四、情境與 FIRE 規劃

情境與 FIRE 規劃涵蓋提早退休、轉職、自雇等多種情境。每個情境需清楚標示假設、輸入、計算邏輯與敏感度；對於資料不足、推估誤差或不可確定處，必須明確標註。

五、內容循環

內容循環只能使用網站內已計算完成的事實，轉寫成 Threads 或 Instagram 等社群內容。每則內容應附上來源與關鍵假設，不得誇大、不作保證，也不得把預測包裝成既定事實。

六、資料循環

網站是唯一可計算系統。原始資料以人工輸入為主，AI 僅讀取網站已產出的計算結果與可用資料。AI 不直接寫回、不自動修改使用者輸入、不自動變更設定。

七、模型路由原則

日常、低風險、可快速驗證的任務使用穩定模型；複雜規劃與跨領域推理使用較強模型；只有在高價值、高不確定性、需要更深推理品質的議題上，才使用高階且成本較高的模型。模型選擇應同時考量品質、風險、成本與可驗證性。

八、版本管理

所有重大假設、方法與計算邏輯的變更，都必須記錄版本號、日期與變更摘要。任何版本都必須能回溯其前一版基準、變更原因與影響範圍，避免系統邏輯在迭代中失去可追蹤性。
