# V1 Operating System design

Authority: user supplied Personal FinOps Planner AI Operating System V1 Baseline Design Record, V1 2026-09-11. User approved updating the website against that baseline on 2026-09-12.

Keep React/Vite and the tested finance.js core. No account, payments, external AI processing of personal data or financial execution. Home becomes a daily dashboard with exactly four metrics. Move original calculator to /diagnosis and add /planning for scenario comparison, deterministic monthly projections, sensitivity, withdrawal-rate target, portfolio allocation analysis and snapshots. Existing article pages remain available. Existing locally stored inputs are loaded, never replaced by AI.

Planning uses explicit start month and baseline input copy, independent named scenarios, salary change month, career break length, loan expiry, annual bonus payment month, nominal return, inflation, withdrawal rate, retirement age and horizon. Bonuses and monthly investments are limited to actual cash. Monthly closing cash and invested assets remain nonnegative; unfinanced expenses are recorded as cumulative shortfall, never hidden. No stochastic success probabilities. Investments use total return inclusive of dividends; no extra dividend addition. Retirement spending is today's currency, inflated monthly. Mortgage/personal-loan payment streams stop after their specified remaining months. Unknown term with nonzero payment is invalid for a projection. Home/other debt is not projected; clearly report cash plus investment assets for FIRE.

Manually save immutable scenario revisions and input/results versions in localStorage with bounded validation. Imported backups are staged/validated before explicit user replacement. Each snapshot references a saved revision and a closing month. FIRE deviation compares actual investment assets with same month's projected investment assets; no baseline means no deviation. Existing diagnosis inputs remain in their existing key; planning writes do not silently update diagnosis.

Content: use only website-computed public synthetic facts. Preserve existing authorized legacy schedule as explicitly outside V1; do not change cron configuration. Make its content generation comply by deriving deterministic fact text, source and assumptions. Reject ungrounded generated claims or use deterministic fallback. Track model choice/usage/version without recording secrets. Draft content in planning is local and only copied by user. Model routing selects stable for easy verification and requires explicit configured stronger/high-end models for complex/high uncertainty tasks; never silently escalate or execute transactions.

Version major method changes with parent version, rationale, date and impact. Baseline file text stored in docs/governance. Existing static diagnosis remains explicitly static; monthly projection has its own version. Responsive layout and keyboard labels are required.
