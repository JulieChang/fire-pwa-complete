# Personal FinOps Planner：產品化路線

2026-09-09｜建議方案，未實作的功能均標示於下。此版本未串接金流、未開放訂閱、未新增使用者帳號。

## 定位

幫助有固定收入、獎金與多個生活目標的使用者，回答「我每個月到底可以投資多少，以及這個選擇會怎樣影響未來」。以可解釋的情境規劃與每月回顧形成持續價值。

目前的 AdSense 工作解決公開內容、抓取與廣告驗證的基礎問題。是否有足夠流量適合廣告、是否有人願意付費，仍需要實際驗證。不要將審核通過當作產品市場需求已成立。

## 免費與付費的建議分界

| 使用需求 | 免費基礎版（現有或本版完善） | 付費規劃版（尚未實作） |
|---|---|---|
| 看懂目前財務狀況 | 單一試算、現金月數、分項解釋、公開文章 | 不用把基礎理解設成付費門檻 |
| 探索未來選擇 | 手動修改數字後重新試算 | 多個命名方案並排比較、差異歸因 |
| 規劃重大時點 | 顯示靜態假設與限制 | 按月模擬貸款結束、獎金實際入帳、轉職、退休、旅遊付款 |
| 維持進度 | 本機保留最近輸入、瀏覽器列印 | 月度快照、預算對照實績、目標偏差與定期檢視 |
| 文件與資料 | 保留現有分享與列印功能 | 可重現且有版本記錄的完整規劃報告、跨裝置同步 |
| AI 輔助 | 不必依賴 AI 才能計算 | 可選：解釋已驗算的結果與差異；限制額度、顯示來源與假設 |

以上是產品假設，不是已驗證的定價方案。先驗證單次付費報告與訂閱服務何者符合使用頻率；只在使用者有定期回顧需求時設計訂閱。

## 第 1 階段：可信的基礎版本（本次交付）

- 原始計算抽成 `src/finance.js`，可獨立測試與重用。
- 本月實領收入與年度平均分離，分配守恆、投資上下限驗證。
- 公開模型公式、資料年分、家庭／個人口徑與退休推估限制。
- 靜態預先渲染、每頁 canonical 與標題、網站地圖、真實 404。
- AdSense 驗證 meta、保留既有 publisher ID；不在尚未批准時注入廣告。
- 清除會被當作公開資產發布的舊 ZIP／設定副本。

尚未完成：正式站部署、真實帳號及 AdSense 後台核對、行動裝置端到端測試、跨裝置資料、付款功能。

## 第 2 階段：讓使用者願意回來（下一版優先）

建議先做三件事：

1. **方案保存與並排比較**：最多三個本機方案，例如維持現況／提高旅費／提早退休。顯示達成時間、最小現金水位、累積投入與預估資產差異。
2. **按月事件模型**：獎金在哪個月入帳、貸款何時結束、旅遊何時付款、退休後停止薪資、何時開始退休金。以資金流入流出模擬，不把所有數字平均攤月。
3. **每月快照與對帳**：輸入實際現金與投資餘額，把新增投入、支出、投資漲跌分開。加入本機 JSON 匯出／匯入和資料清除，先提供使用者可掌控的備份方式。

下一版的資料概念：`plan`（命名方案）→ `input_version`（輸入及假設版本）→ `events`（日期與金額）→ `monthly_results`（按月結果）→ `snapshot`（實績）。每份報告記錄 `calculation_version`，修公式後舊結果仍可追溯。

驗收門檻建議：計畫每月現金守恆；貸款只在有效月份扣款；獎金不會早於入帳日被使用；股利再投入不重複計入總報酬；同樣輸入能產出同樣結果。以假設資料測試，無需蒐集真實帳戶明細。

## 第 3 階段：小規模驗證需求（尚未開始）

建議邀請約 5–10 位目標使用者，先驗證流程而非推銷：

- 能否自行完成一份規劃，並說出下一步要調整什麼？
- 是否真的需要保存第二種方案？最常比較什麼事件？
- 一個月後是否願意回來更新？沒回來的原因是什麼？
- 會為完整單次報告付費，還是為持續追蹤付費？哪些功能值得付費？

這些人數是建議的初步訪談規模，不是市場成功門檻。先確認價值與使用頻率，再做價格實驗。分析事件只記錄「完成試算／儲存方案／回訪」等行為，不送出收入、資產、負債或診斷分數。

## 第 4 階段：付費服務工程（尚未實作）

按以下依賴順序建置：

1. 帳號與資料隔離：驗證登入、以使用者識別碼限制每筆資料讀寫、跨帳號存取測試、備份、刪除與匯出流程。
2. 跨裝置保存：資料庫、輸入版本、衝突處理、復原機制。不要把付款或權限狀態只存在 localStorage。
3. 商品與權益：方案、用量限制、試用與到期規則。登入使用者的付費功能須由伺服器驗證。
4. 金流：先核對營運主體／所在地、幣別、結算方式與服務商支援，再選供應商；處理訂單、簽章驗證、webhook 重送去重、取消、退款和權益同步。
5. 對外營運：實際資料處理政策、使用條款、客戶支援、付款與報告出錯的補救流程、監控與成本限制。

前端可沿用 React／Vite，公開教育頁繼續靜態生成。金流、帳號權益與持久資料由伺服器管理，不需要為了登入就重寫所有試算頁。

## AI 成本與品質

核心數值由確定性程式算出。AI 只解釋結構化結果，不自行產生退休餘額、報酬率或排名。未經使用者同意，不把完整財務資料送到外部模型。

每份可用報告成本 = 模型輸入／輸出成本 + 重試成本 + 運算與儲存分攤 + 必要人工處理。需以實際用量驗證，不能只以單次 token 價格評估毛利。

品質驗收：金額與程式結果一致、未漏述關鍵假設、未將情境達成率描述為機率、未承諾收益、沒有錯用家庭排名。AI 失敗時，仍可提供基本數字與公式，不阻斷核心工具。
